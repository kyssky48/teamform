## 3. 고른 해결 방법 (공고 3장)

7개 기능 모두 어려운 해결로 만들었습니다.

| 기능 | 고른 해결 | 방법 |
|---|---|---|
| 다른 사람의 변경 보기 | 어려운 해결 | `st.fragment(run_every=3)`로 팀 목록, 투표 단추, 결과 안내만 3초마다 다시 그림 (`streamlit_app.py`) |
| 필수 포함 역할을 지킬 수 없는 팀 | 어려운 해결 | 지원할 때 "지원자가 들어간 뒤 남는 자리 < 아직 못 채운 필수 역할 수"이면 막음. 기획자·웹 프로그래머는 서로 다른 학생으로 짝지어 셈 (`teamform/rules.py`의 `missing_required`, `block_reason`) |
| 같은 팀에 대기 중인 지원이 여럿 | 어려운 해결 | 그때의 팀원 모두가 찬성한 순간 정원·주 역할·필수 역할 자리를 다시 검사함. 처리 순서는 투표가 끝난 순서 (`teamform/service.py`의 `vote`) |
| 마지막 자리에 두 명이 동시에 들어감 | 어려운 해결 | `tf_members`의 `(team_id, slot_no)` 기본 키와 `student_id` 유일성 제약. 충돌하면 그 지원은 거절 (`schema.sql`, `teamform/pg_store.py`의 `add_member`) |
| AI 응답이 늦을 때 | 어려운 해결 | 모델마다 요청부터 응답을 다 받을 때까지 전체 120초를 따로 돈 스레드로 재서 끊고 다음 모델로 넘어감 (`teamform/ai.py`의 `with_deadline`) |
| 3차 모델까지 실패 | 어려운 해결 | 다섯 가지 검사를 모두 통과하는 배정을 모든 경우를 따져 찾음. 없으면 AI를 부르지 않고 이유를 보여 줌 (`teamform/rules.py`의 `solve`, `infeasible_reason`) |
| AI 대기 중 화면 | 어려운 해결 | `assign_status`에 "n차 모델(이름) 응답을 기다리는 중 (35초 / 120초)"처럼 몇 차 모델을 몇 초째 기다리는지 2초마다 보여 줌 |
| DB(Supabase)가 일시정지되지 않게 | 어려운 해결 | GitHub Actions가 매일 09:00(KST)에 DB에 질의 한 번을 보냄 (`.github/workflows/db-ping.yml`, `scripts/db_ping.py`) |

## 5. 오픈라우터 AI 모델 호출 실패 사례

**사례 1: 1·2차가 120초 제한에 걸리고 3차가 사용량 초과 → 앱이 스스로 배정 (배포한 앱, 부록 3 어려움 15단계, 10/23 19:04~19:06)**

## 6. 클로드가 잘못된 추론이나 답변을 한 사례

**사례 1: SQL 안의 `'{}'`를 파이썬 `str.format`이 자리 표시로 읽음**
- 클로드가 만든 `PgStore`가 SQL 문자열에 `'{}'`(빈 배열)를 넣고 `.format()`을 써서, 실제 DB에서 `IndexError`가 남
- 메모리 저장소로만 시험해서 드러나지 않았고, 실제 Supabase로 저장소 시험을 돌리다 알아챔
- 커밋 `1f64019`에서 `'{{}}'`로 고침

**사례 2: 관리자 계정을 앱이 켜질 때 한 번만 맞춰도 된다고 판단함**
- 클로드가 실제 DB 시험을 돌리면서 관리자 비밀번호 해시를 시험용 값으로 덮어씀. 배포한 앱은 관리자 계정을 시작할 때만 맞추므로 배포한 앱의 관리자 로그인이 "막힘: 학번이나 비밀번호가 틀림"으로 막힘
- 배포한 앱으로 시나리오를 돌리다 알아챔
- 커밋 `3db40c6`에서 관리자 로그인 때마다 `ADMIN_PASSWORD`로 맞추게 하고, 시험이 관리자 계정을 건드리지 않게 고침

**사례 3: AI를 오래 기다려도 화면 연결은 유지된다고 가정함**
- 모델 하나를 120초 기다리는 동안 화면에 아무것도 보내지 않아, 배포한 앱에서 브라우저 연결이 끊기고 관리자가 로그인 화면으로 돌아감. 배정도 2차 모델 뒤에서 멈춰 3차 모델과 앱 자체 배정까지 가지 못함
- 배포한 앱에서 부록 3(어려움) 15단계를 돌리다 알아챔. AI 호출 기록에 18:34(1차), 18:36(2차)만 있고 3차 기록이 없음([`img/hard-15-ai-logs.png`](img/hard-15-ai-logs.png)의 4·5번째 줄)
- 커밋 `5f89b74`에서 기다리는 동안 2초마다 경과 시간을 화면에 갱신하게 고침. 고친 뒤 같은 단계에서 1·2차 120초, 3차 429를 거쳐 확정까지 끝남(5항 사례 1)

**사례 4: 파일 맨 위의 생성 시각을 시스템 시각을 확인하지 않고 적음**
- 새 파일 22개에 실제보다 최대 1시간 30분 늦은 시각을 적음
- 시스템 시각(`date`)과 비교하다 알아챔
- 커밋 `2132269`에서 파일 생성 시각과 처음 커밋 시각 가운데 이른 쪽으로 고침

## 7. 앱에서 발견한 문제점과 개선할 점

**1. AI 배정이 최악의 경우 4분 넘게 걸림 (부록 3 어려움 15단계)**
- 무료 모델이 느리면 1차 120초 + 2차 120초 + 3차를 기다리는 동안 관리자는 "AI가 배정안을 만드는 중"만 보며 기다려야 함
- 화면: [`img/hard-15-ai-waiting.png`](img/hard-15-ai-waiting.png) (AI 배정을 누르고 5초 뒤)
- 실제 기록: 10/23 19:04~19:06에 1·2차가 120초씩 걸림([`img/hard-15-ai-logs.png`](img/hard-15-ai-logs.png))
- 개선안: 앱이 먼저 만든 배정안을 바로 보여 주고 AI 결과는 나중에 바꿔 끼우기, 또는 응답이 빨랐던 모델을 앞 순서로 자동 조정

**2. push한 뒤 Streamlit Cloud가 코드의 일부만 다시 읽음**
- `streamlit_app.py`는 새 버전인데 `teamform/auth.py`는 예전 모듈이 남아, 로그인할 때 `TypeError`가 남(10/23, 커밋 `3db40c6`을 push한 직후)
- Streamlit Cloud에서 Reboot app을 눌러야 해결됨. 그래서 마감 전 마지막 push 뒤에는 반드시 Reboot하고 로그인을 확인함

**3. 처음 README를 쓸 때 알고 있던 작은 문제 (커밋 `b46f336`에서 고침)**
- AI 배정을 다시 누르면 그 실행이 끝날 때까지 이전 진행 안내와 새 진행 안내가 섞여 보였음 → 누르는 순간 이전 안내를 지움(화면 시험 `test_assign_again_shows_only_new_progress`)
- 배정이 불가능할 때 "팀 사이에 학생을 나눌 방법이 없음"으로만 안내했음 → 먼저 "주 역할이 프론트엔드 디자이너인 학생 3명을 받을 수 있는 팀이 2개뿐 (팀2, 팀3)", "웹 프로그래머를 맡을 학생이 1명 모자람 (필요한 팀: 팀1, 팀2 / …)"처럼 구체적인 이유를 찾아 보여 줌. 무작위 명단 4,000개(배정 불가 2,633개)로 재 보니 "팀 사이…"로만 안내되던 경우가 1,240개에서 16개로 줄었음
- 명단을 다시 올려 같은 학번이 다른 학생이 되었는데도 예전 이름으로 남아 있었음 → 이름이 바뀌었으면 로그인 화면으로 돌려보냄
- CSV 오류 안내의 줄 번호가 빈 줄을 건너뛴 번호여서 실제 파일 줄과 달랐음 → 빈 줄까지 셈

## 참고

### 시험과 연습 시나리오
- `pytest`로 규칙, 지원·투표, 마감·배정, AI 실패 처리, CSV 읽기를 시험합니다. 화면 시험(`tests/ui`)은 Playwright로 공고 2.7절의 key만 써서 화면을 조작합니다.
- 부록의 연습용 시나리오 3개는 **시험 코드에만** 있습니다(`tests/scenarios.py`, `tests/data/*.csv`). 앱 코드(`streamlit_app.py`, `teamform/`)는 이 데이터를 읽지 않고, 학생 이름이나 순서로 결과를 정하지 않습니다.
- 실제 Supabase로 도는 시험은 `TEAMFORM_PG_TESTS=1`일 때만 돌고, 실제 DB의 `tf_` 데이터를 지우므로 채점 기간에는 돌리지 않습니다.
- 저장소를 공개하기 전에 `.venv/Scripts/python scripts/check_secrets.py`로 `.env`의 실제 비밀 값이 커밋 기록이나 파일에 없는지 확인합니다(값은 출력하지 않고 "있음/없음"만 보여 줌).

### 로컬에서 실행
```bash
py -3.12 -m venv .venv
.venv/Scripts/python -m pip install -r requirements-dev.txt
.venv/Scripts/python -m streamlit run streamlit_app.py
```
`.env`에 `OPENROUTER_API_KEY`, `DATABASE_URL`(Supabase Session pooler 주소), `ADMIN_PASSWORD`를 넣어야 합니다(`.env.example` 참고). `.env`는 git에 올라가지 않습니다.
