# 팀 편성 앱 구현 계획

> **에이전트 작업자용:** 필수 하위 스킬: superpowers:subagent-driven-development(권장) 또는 superpowers:executing-plans로 작업을 하나씩 실행한다. 단계는 체크박스(`- [ ]`)로 표시한다.

**목표:** 공고 3장의 7개 기능을 모두 어려운 해결로 만든 Streamlit 팀 편성 앱을 Streamlit Community Cloud에 배포한다.

**구조:** 규칙(`rules.py`)과 동작(`service.py`)은 Streamlit과 DB를 모르는 순수 파이썬으로 만든다. 저장은 `Store` 인터페이스 뒤에 두고, 테스트는 `MemoryStore`, 실제 앱은 `PgStore`(Supabase)를 쓴다. `streamlit_app.py`는 화면만 그리고 `service` 함수를 부른다.

**기술:** Python 3.12, Streamlit(`st.fragment`), psycopg 3, bcrypt, requests, python-dotenv, pytest, Playwright(화면 key 시험)

**설계 문서:** `docs/PRD.md`. 이 계획은 PRD를 근거로 하므로 둘을 함께 읽는다.

## 검토 중점 (테스트가 놓치기 쉬운 입력)

1. **BOM, 칸 앞뒤 공백, 역할 안의 겹친 공백, 빈 `sub_roles`가 섞인 CSV**는 오류 없이 읽혀야 한다 → 작업 1 `test_parse_messy_csv`
2. **지원한 뒤에 팀원이 된 학생**도 그 지원에 투표해야 하며, 그 사람이 투표하기 전에는 승인되지 않는다 → 작업 4 `test_new_member_must_also_vote`
3. **AI 배정안이 이미 팀에 있는 학생을 옮기거나, 없는 학번이나 없는 팀 번호를 넣은 경우**는 검사에서 걸러야 한다 → 작업 3 `test_validate_plan_rejects_moves_and_unknowns`
4. **학생 계정이 관리자 동작 함수를 부르면** 막혀야 한다(화면 숨김과 별개) → 작업 5 `test_student_cannot_use_admin_actions`
5. **명단을 다시 올린 뒤** 전에 로그인한 학생 화면은 로그인 화면으로 돌아가고, 지난 지원·투표·마감 표시는 남지 않아야 한다 → 작업 5 `test_restart_clears_everything_but_admin`, 작업 8 `test_restart_logs_out_removed_student`

  - `infeasible_reason`: 아래 순서로 처음 걸리는 것을 낸다. ① 남은 자리 합 < 남은 학생 수 ② 팀마다 그 팀만 따로 놓고, 남은 학생 가운데 빈자리 수 이하의 학생을 골라 넣어(주 역할 중복 없이) 그 팀의 `team_errors`가 빈 목록이 되는 조합이 하나도 없으면, 팀원을 그대로 둔 채 계산한 `team_errors`의 필수 역할 문구를 낸다 ③ 빈 팀 수 × 2 > 남은 학생 수 ④ 나머지는 `"팀 사이에 학생을 나눌 방법이 없음"`
- [ ] **4단계: 통과 확인** — 같은 명령 → PASS
- [ ] **5단계: 무작위 시험** (`tests/test_solver_random.py`) — 씨앗을 고정해 200번: 팀 3~4개, 학생 8~16명, 역할 무작위, 지원을 흉내 내어 일부 학생을 규칙에 맞게 미리 팀에 넣고 1명뿐인 팀은 비운 뒤, `solve` 결과가 있으면 `validate_plan(...) == []`, 없으면 모든 배정을 따로 다 세어(학생 ≤ 8명일 때만) 정말 없는지 확인한다. 한 번에 1초 이내
